## Как этим пользоваться?

### Сборка

```
binaries/src/esc/build.sh          # результат по умолчанию: binaries/esc
# При необходимости можно явно задать OUT и ZIG
```

Скрипт вызывает `zig cc -target arm-linux-musleabihf -O2 -static` (armv7, musl, статический бинарник), кэш держит в `/tmp`. Требуется `zig`; для arm64-сборки нужен другой target.

После пересборки обновите контрольные суммы: `(cd binaries && sha256sum esc rootd > SHA256SUMS)`. `scripts/get-root.py` сверяет их перед отправкой `esc` на станцию.

### Общее поведение всех команд

Перед разбором аргументов бинарник ставит обработчики `SIGBUS`/`SIGSEGV` (неисправные окна чтения — ожидаемая часть работы), переименовывает себя через `prctl(PR_SET_NAME, "esc36449")`, чтобы `scan` мог найти свой процесс по уникальному имени, и печатает `escalate: pid=… uid=…`. В конце каждой команды выводится строка `RESULT: …` — по ней удобно проверять успех; код возврата 0 — успех, 1 — ошибка выполнения, 2 — ошибка аргументов/не удалось открыть `/dev/mali0`.

### `scan`

```
./esc scan
```

Разведка, только чтение. Поднимает ридер (берёт у драйвера Mali таблицу страниц), находит живой образ ядра по ARM64-магии от PA `0x1080000`, находит `init_task` по содержимому (`"swapper"`, `pid==tgid==0`, `mm==NULL`), через него — `init_cred` с реальными привилегированными значениями, а затем обходит список задач до своего собственного `cred`. Выводит `RESULT: ESC-SCAN OK - init … cred … tss … sid … kcap … ksid …` и счётчики `cycles/windows/blocks`. Это база для остальных команд: адреса, которые она печатает, потом используются в `read`/`flip`.

### `dump [PATH [START LENGTH]]`

```
./esc dump                                     # весь образ ядра
./esc dump /data/local/tmp/k.img               # то же, в указанный файл
./esc dump /data/local/tmp/k.img 0x1090000 0x10000   # фрагмент
```

Только чтение памяти ядра. Сам находит образ ядра, постранично читает диапазон и пишет его в файл (по умолчанию `/data/local/tmp/kallsyms-live.img`) с правами 0600. Путь обязан быть внутри `/data/local/tmp/`, иначе отказ. `START` должен быть выровнен по 4 КБ и лежать внутри образа; `LENGTH` по умолчанию — до конца образа. На каждой странице до трёх попыток чтения, в конце печатается sha256 дампа и `RESULT: DUMP OK …`. При сбое недописанный файл удаляется (`RESULT: DUMP FAILED`).

### `read PA`

```
./esc read 0x291352c
```

Читает одно 32-битное слово по физическому адресу через свежее окно, без записи в память ядра. `PA` должен быть выровнен по 4 и быть меньше 2 ГБ (`ESC_RAM_SIZE`). Выводит `read: pa=… value=… (0x…)` и `RESULT: READ32 OK …`. Это основной способ проверить адрес перед `flip`.

### `flip PA OLD NEW`

```
./esc flip 0x291352c 1 0
```

Единственная команда, которая пишет в память ядра. Меняет одно 32-битное слово по `PA` с `OLD` на `NEW`, но только при совпадении: сначала читает текущее значение, и если оно не равно `OLD`, то отказывается писать (`RESULT: FLIP ABORT before mismatch (no write)`). После записи перечитывает значение, проверяет, что оно равно `NEW`, и при расхождении возвращает `OLD` обратно (rollback). Попутно показывает содержимое `/sys/fs/selinux/enforce` до и после — удобно, когда `flip` применяется к `selinux_enforcing` (офсет `0x291352c` для сборки 5000000921). Вывод: `RESULT: FLIP OK …` либо `RESULT: FLIP FAILED rollback=OK|INCOMPLETE`.

### Типичный порядок работы

1. `./esc scan` — получить адреса `init`, `cred`, `tss` и `sid`.
2. `./esc read <PA>` — проверить конкретное слово, прежде чем его менять.
3. `./esc flip <PA> <OLD> <NEW>` — точечно изменить значение (с проверкой и откатом).
4. `./esc dump` — если нужен снимок образа целиком для разбора офлайн.
