# Получение root-доступа на Яндекс Станции Макс

Проект описывает экспериментальный способ получить постоянный root-доступ к Яндекс Станции Макс. Это предварительное описание текущей минимальной версии; перечень проверенных моделей, прошивок и ограничения будут уточняться по мере испытаний.

## Поддерживаемое устройство и исходные условия

- **Модель:** Яндекс Станция Макс, ревизия YNDX-0008, YNDX-00052 или YNDX-00053. Метод потенциально применим ко всем трём ревизиям, поскольку они используют общую прошивку. Практически проверена только **YNDX-00053**.
- **Возраст устройства:** станция должна быть выпущена ориентировочно **до октября 2026 года**. Точной информации о factory прошивках более свежих станций на данный момент нет.
- **Текущая прошивка:** любая — процедура начинается со сброса к заводской прошивке. Важно не только текущее состояние, но и версия заводской прошивки, которую устройство восстанавливает.
- **Подготовка:** для настройки понадобится компьютер или внешний сервер. Текущая версия руководства адаптирована под стенд на Linux (i use arch btw), но потенциально все можно запустить как на macOS, так и на Windows, но скрипты могут потребовать адаптации.

## Что делает метод

В общих чертах процедура переводит станцию с подходящей заводской прошивки на сборку **5000000921**, получает временный root-доступ с помощью эксплойта **CVE-2022-36449**, устанавливает демон `rootd` для выполнения команд от root и настраивает повторное получение permissive-режима и доступного через ADB root после перезагрузок. К текущему моменту нет подтвержденного способа удержать ADB без внешнего сервера в состоянии enforcing

Сервер нужен на этапе первоначальной настройки: он подменяет ответы Яндекса и передаёт команды, необходимые для включения ADB и установки прошивки 921. После завершения настройки станция должна работать автономно, без этого сервера.

## Этапы процесса

Подробно процесс, команды и скрипты описаны в [GUIDE.md](GUIDE.md), здесь только описание процесса.

### 1. Сброс к заводским настройкам

1. Отключите питание станции.
2. Зажмите кнопку Алисы.
3. Не отпуская кнопку, подключите питание.
4. Продолжайте удерживать кнопку, пока светодиодное кольцо не загорится жёлтым.

Во время сброса станция восстанавливает заводскую прошивку. **Не отключайте питание и не прерывайте процесс:** потеря питания на этом этапе может привести к кирпичу.

### 2. Первоначальная настройка через вспомогательный сервер

Пока станция проходит первоначальную настройку, работает сервер проекта, подменяющий ответы Яндекса. В рамках этого этапа он:

- передаёт команду на включение ADB;
- инициирует установку прошивки 5000000921.

Обоснование выбора этой версии связано с доверием к сертификатам, использованным при подмене HTTPS-ответов; подробности приведены ниже. 

### 3. Получение временного root-доступа

После установки прошивки 921 применяется эксплойт **CVE-2022-36449**. Он используется для переключения SELinux в permissive-режим и получения возможности выполнять команды из root shell.

### 4. Установка `rootd`

Из root shell устанавливается демон `rootd`, предназначенный для выполнения команд с UID 0. Его запуск добавляется в `/odm/etc/init/rootd.rc`, чтобы демон стартовал вместе с системой. 

### 5. Настройка после перезагрузки

После перезагрузки SELinux возвращается в enforcing-режим. Поэтому отдельный скрипт повторно использует тот же эксплойт для включения permissive-режима. Затем настраивается постоянный доступ через ADB.

**Ожидаемый результат:** станция запускается автономно, без вспомогательного сервера; ADB доступен, SELinux находится в permissive-режиме, а `rootd` позволяет выполнять команды от UID 0.

## Почему нужна прошивка 921 и станция подходящего возраста

Сервер подменяет ответы, передаваемые по HTTPS. В октябре 2026 года были скомпрометированы приватные ключи **eMuhdra**; на их основе для метода подготовлены сертификаты. В более новых прошивках эти сертификаты уже не считаются доверенными, тогда как более ранняя заводская прошивка им доверяет. Поэтому важна заводская прошивка, восстанавливаемая при сбросе, а не только версия, установленная на станции до начала процедуры.

После восстановления подходящей заводской прошивки сервер использует доверие к этим сертификатам, чтобы передать команды первоначальной настройки и установить версию 921. 

## Результат и ограничения

После успешного завершения ожидается, что станция:

- работает на прошивке 5000000921;
- имеет ADB-доступ;
- запускает `rootd` при старте системы;
- позволяет выполнять команды от UID 0;
- загружается с SELinux в permissive-режиме;
- не зависит от вспомогательного сервера после завершения первоначальной настройки.
